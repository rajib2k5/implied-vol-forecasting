# Data provenance

## What this app ships

- **`src/data/term-structure.synthetic.json`**: a 5-tenor (9D, 30D, 3M, 6M, 1Y) by 60-date synthetic
  term structure that drives the 3D placeholder page.
  - **Source**: generated by the seeded generator in `src/lib/termStructure.ts` (`mulberry32`,
    seed `20261027`); no vendor data is involved.
  - **Regenerate**: `npm run gen:fixture` (needs Node 22.18 or newer). A unit test fails if the
    committed file differs from what the generator produces.
  - **Labelling**: the UI shows a "synthetic data" badge wherever the fixture is drawn. The file
    carries `"data_mode": "synthetic"`, which the deploy guard (below) requires of every JSON data file.
  - **Caveats**: the dates are weekday labels only (no holidays) and are not real market dates. The
    curve is a mean-reverting model plus one scripted spike, so it is a teaching stand-in, not a
    statement about real volatility.

## What this app does not ship

- **CBOE volatility index history, FRED series and Yahoo Finance (yfinance) prices are not
  committed or redistributed.** CBOE's terms restrict use to personal, non-commercial purposes. The
  Python pipeline fetches these at run time into a local cache outside the repository
  (`$VOL_DATA_DIR/implied-vol-forecasting/raw/`, where `VOL_DATA_DIR` defaults to `~/data/vol-projects`).
- **Nothing a daily series can be rebuilt from.** Per-date forecasts, errors and equity curves count
  as the data: the cumulative sum of a random-walk forecast's errors rebuilds the VIX path. So real
  per-date results are never committed, and never bundled into `dist/`.

## Where results will come from

From milestone 1 onward the Python pipeline exports versioned JSON (`schema_version`,
`generated_at`, `source_commit`, `source_dirty`, `data_mode`) through `tools/export_app_data.py`. The
decisions are in ADR 0001 (D1 and D2); the files are described by `schemas/app-data/` and
`docs/architecture/data-model.md`. There are two places for it, and they are not the same:

- **Synthetic JSON, committed**: `app/public/data/synthetic/{dataset}.json` (`data_mode: "synthetic"`).
  `ivf.data.synthetic` writes Cboe-shaped files from a seed, and the same loaders, pipeline and
  exporter then run on them. `vite build` copies `public/` into `dist/`, so this is the data a
  build or a deploy ships. The UI will show a badge on every view, read from `data_mode`.
- **Real JSON, never in the repository**: `$VOL_DATA_DIR/implied-vol-forecasting/app-data/real/{dataset}.json`
  (`data_mode: "real"`). The Vite dev server serves it at `/data/real/`, in dev only. It is
  deliberately **not** under `public/`: `vite build` would copy it into `dist/`, and one deploy would
  redistribute vendor data. `.gitignore` also lists `app/public/data/real/` as a second layer.
- **Real-data results: only the publication set P** (ADR 0001 D2, amended M0 review D). The goal is
  that nothing committed, including git history, lets anyone reconstruct the daily series of any
  vendor index or ETP, or a material part of it. So the only real-data-derived numbers that may be
  committed (in `reports/*.agg.csv`, the README, docs or screenshots) are the closed set P. Every one
  is unitless and rounded, and is computed per whole period (`dev`, `holdout`), never per regime or
  sub-period:
  - RMSE and QLIKE of each model as a ratio to the random walk's (3 significant figures); MAE and MAPE
    the same way, flagged as not consistent for the mean;
  - Diebold-Mariano statistic (HLN-corrected) and its p-value (2 decimals);
  - Mincer-Zarnowitz as pass/fail booleans only: no coefficients, no p-values;
  - Sharpe, PSR and DSR (2 decimals), the number of trials (exact), annualised turnover (2 s.f.);
  - the AR(1) half-life of ln(index), in sessions (2 s.f.);
  - `n`, the count behind each number.

  Nothing in vol points or prices; no moments (means, standard deviations, skew, kurtosis); no
  coefficients; no returns, drawdowns, extremes or quantiles; no regime cells. Figures may only be
  drawn from P values (for example holdout RMSE ratio by model), never a real error surface,
  histogram or time plot. Two more rules:
  - **R1: one release per frozen `data_end`, no corrections.** P is committed once. A wrong value is
    withdrawn by a later commit that deletes it and adds an erratum with no replacement number. It is
    never corrected in place, because git keeps the old value and the old and new values together
    would be a second publication.
  - **Q: dated index levels in prose.** Only for a named market event, cited to a public source; never
    a VXX or SVXY price; never a session within 21 sessions of a period boundary (`train_start`, the
    first and last origin of dev and of the holdout, `data_end`).

  D2 stays Proposed until the user accepts it, and it is an engineering rule, not legal advice. Its
  stated residuals (joint inversion of P with strong outside knowledge, scale-tied models, quoted
  closes, legal sufficiency) are in the ADR. The app itself never renders real results from the
  repository: real JSON stays local and is served only by the dev server.
- **The deploy guard** (ADR 0001 D2): `scripts/guardDist.mjs`, run as `npm run guard:dist`. It is the
  last line of defence, after the real JSON living outside the repo and the `.gitignore` entry.
  `npm run verify` runs it after `npm run build`, and the Dockerfile runs it as a build step, so a
  failing guard fails both. It looks at the whole app directory except the top-level `node_modules/`,
  `coverage/` and `.git/`, and exits non-zero, naming the file and the rule, for each of:
  - **symlink**: any symlink anywhere. The test runs first, on every entry, so no file-name filter can
    skip a link, and links are never followed. A link can reach data outside the repo, and
    `vite build` copies what a link in `public/` points at into `dist/` (measured for file and folder
    links, Vite 7.3.7).
  - **marker**: any file containing `"data_mode":"real"`, however spaced or quoted (`"data_mode" : "real"`,
    `{data_mode:"real"}`, the escaped form inside a JS string), in `dist/` or anywhere else under the
    app. Anywhere, because Vite strips the literal from an imported JSON module (it becomes
    `{data_mode:X}` with `X="real"` kept elsewhere in the bundle), so a real export copied to
    `app/realdata/` and pulled in by a relative import or `import.meta.glob` never shows the marker in
    `dist/`. Exempt: files that only describe the marker (`*.md`, `*.test.ts`, `*.test.tsx`,
    `*.test.mjs` and the guard script itself).
  - **allowlist**: every `.json` file under `src/`, `public/` and `dist/` must be a JSON object whose
    top-level `data_mode` is `"synthetic"`, and nothing but `.json` may sit in `src/data/`,
    `public/data/` or `dist/data/`. Real data may carry no marker at all (`df.to_json()` writes none),
    so the guard asks for a positive label instead. `scripts/genFixture.ts` emits it into the M0
    fixture, `parseTermStructure` requires it, and the Python-exported
    `public/data/synthetic/manifest.json` already has it.
  - `public/data/real/` or `dist/data/real/` existing at all, even empty; `dist/` missing or empty (a
    guard that scanned nothing must not pass).

  It never prints file contents, only paths and rule names, and never a JSON parse error, which quotes
  the text around the fault. `scripts/guardDist.test.mjs` tests it against temporary folders.

  **What it cannot catch.** It is a tripwire for accidents, not a defence against someone who hides
  data. These get through, and a green `guard:dist` says nothing about them:
  - Deliberate hiding: an obfuscated marker such as `"\u0072eal"`, base64 or gzip data outside the data
    directories, UTF-16 text (the marker is read as ASCII).
  - Real data without the marker in anything that is not a `.json` file under `src/`, `public/` or
    `dist/`: pasted into a `.ts`/`.tsx` literal, a `?raw` CSV in `src/lib/`, or a CSV placed in `public/`
    outside `public/data/`.
  - JSON without the marker outside `src/`, `public/` and `dist/`, for example `app/realdata/vix.json`
    imported by a relative path. Only the marker scan reaches it, and `df.to_json()` output has no
    marker. A test pins this limit.
  - Real data inside a file the marker scan exempts by name: a `.md` file or a `*.test.*` file. (The
    data directories still turn away anything that is not a synthetic `.json`.)
  - A JSON file that carries real data but labels itself `"data_mode": "synthetic"`. The allowlist
    trusts the label.
  - Values baked in at build time through `VITE_*` variables in `.env*` files.
  - Anything fetched at run time from another origin, and anything outside the app directory.
- **`.dockerignore`** also lists `public/data/real`, `.env` and `.env.*`, so those never enter the
  build context.

The payload shape in `src/lib/termStructure.ts` is provisional until the exporter fixes the contract
in milestone 1.
